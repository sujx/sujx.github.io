IT服务规划设计

规划涉及处于整个IT服务生命周期的前端，帮助IT服务提供方了解客户需求并进行全面需求分析，然后通过服务要素、服务模式和服务方案的具体设计，最终形成SLA。其主要目的在于：

  1. 设计满足业务需求的IT服务
  2. 设计SLA、策略方法和指标
  3. 设计服务过程及其控制方法
  4. 规划服务组织架构、人员编制、岗位及任职要求
  5. 识别风险，定义风险控制措施和机制
  6. 识别和规划支持服务所需的技术及资源
  7. 评估IT服务成本，制定服务预算，控制服务成本
  8. 制定服务质量管理计划

IT服务规划设计活动

规划设计的活动

  1. 服务需求识别
  2. 服务目录设计
  3. 服务方案设计
    1. 服务模式设计
    2. 服务级别设计
    3. 人员要素设计
    4. 过程要素设计
    5. 技术要素设计
    6. 资源要素设计
  4. 服务成本评估
  5. 服务级别协议设计

关键成功因素

  1. 确保规划设计考虑全面
  2. 当服务变更或补充规划设计的任一独立元素时，要综合考虑有关职能、管理和运营层面问题
  3. 明确重点，充分沟通
  4. 策划、实施、检查和改进（ PDCA ）

服务目录管理

目的

  1. 为所有商定服务提供单一、连贯的信息来源
  2. 确保所有获准使用相关服务的人能够知道这些信息

种类

  1. 业务服务目录
  2. 技术服务目录

活动

  1. 确定小组成员
  2. 列举服务清单
  3. 服务分类与编码
  4. 服务项详细描述
  5. 评审并发布服务目录
  6. 完善服务目录

关键成功因素

  1. 确保向需方提供的每个服务都是独立的
  2. 根据实际需求，对服务内容进行控制和衡量
  3. 服务成本可以根据客户需求的不同而进行改变
  4. 客户容易认可和感受对服务成本有较大影响的服务

服务级别协议

SLA是在一定成本控制下，为保障IT服务的性能和可靠性，服务供方与客户间定义的一种双方认可的协议。

服务需求识别

目的

  1. 了解客户的基本需求，分析潜在客户需求
  2. 了解客户对系统可用性和连续性的需求
  3. 进行合理的IT服务资源配置
  4. 为预算IT服务成本、设计定价和收费模式奠定基础

活动

  1. IT服务可用性需求识别
    1. 平均无故障时间
    2. 平均故障修复时间
    3. 平均故障间隔
  2. 业务连续性需求识别
  3. IT服务能力需求识别
  4. 信息安全需求识别
    1. 机密性
    2. 完整性
    3. 可用性
  5. 价格需求识别
  6. IT服务报告需求识别

关键成功因素

  1. 明确服务范围、服务内容和服务目标
  2. 识别客户对可用性、连续性、信息安全、服务能力等方面需求
  3. 与需方充分沟通，全面了解明示和隐含服务需求

服务方案设计

  1. 选择的IT服务模式与客户需求一致
  2. 跟踪客户需求变化，及时调整IT服务模式
  3. 具备同时提供多种IT服务模式的能力
  4. 人员配置和资源配置与IT服务模式匹配

服务级别设定

目的

  1. 通过对IT服务绩效的协商、监控、评价和报告等固定运营流程，来维持和改进IT服务的质量
  2. 采取适当的行动来消除或改不符合级别要求的IT服务
  3. 提高客户满意度，改善客户关系
  4. 督促IT服务供方

活动

  1. 了解服务内容
  2. 确定服务范围
  3. 定义服务级别目标
  4. 明确双方职责
  5. 识别风险
  6. 对服务级别设定的评审和修改
  7. 服务级别的谈判和沟通

关键成功因素

  1. 充实服务级别设定
  2. 设定过程中，服务级别应当获得大多数人的同意和认可
  3. 充分考虑客户需求
  4. 验证服务目标是否可实现
  5. 正确识别供方服务能力
  6. 明确各方的责任

人员要素设计

目的

  1. 确保服务团队组织架构与业务需求和服务模式相适应
  2. 确保配置服务人员数量能够满足服务和成本两个方面需求
  3. 确保人员能力持续满足服务需求
  4. 保持服务人员稳定的工作状态
  5. 保持服务人员的连续性

活动

  1. 人员岗位和职责设计
  2. 人员绩效方案设计
  3. 人员培训方案设计
  4. SMART原则：明确的、可以衡量的、可以达到的、可以实现的、时限性

资源要素设计

目的

  1. 确保服务供方提供足够的资源能力
  2. 确保服务供方可以使用过有效的手段和方法受理客户的服务请求
  3. 分析当前的业务需求并预测将来的业务需求
  4. 确保当前的服务资源能够发挥最大的效能、提供最佳服务品质

活动

  1. 服务工具选择
  2. 服务台设计
  3. 备件以及备件库设计
  4. 知识库设计

关键成功因素

  1. 服务人员能力达标
  2. 服务台的职能明确，服务过程规范
  3. 备件管理规范与SLA条款一致
  4. 有效的监控平台
  5. 及时根据服务级别和服务需求的变更调整服务资源的配置
  6. 第三方的支持服务级别应当满足服务需求

技术要素设计

目的

  1. 提高服务质量
  2. 减少人员流失代理的损失
  3. 提高服务效率
  4. 降低服务成本
  5. 提供一致的技术标准
  6. 根据实际需求选择所需技术

活动

  1. 技术研发
  2. 发现问题技术
  3. 解决问题的技术

关键成功因素

  1. 服务人员技术能力达到岗位要求
  2. 正确识别服务需方要求或者技术发展趋势
  3. 重视技术方面的使用、管理和维护，建立发现和解决问题的技术体系

过程要素设计

过程管理模型

过程是为了达到某个目的或者目标，而以确定的方式执行或者发生的一个或一系列有规律的行动或者活动。规程，也成为标准作业程序（ SOP ），是指将某一时间的标准操作步骤和要求以统一的格式描述出来，用来指导和规范日常的工作。简单理解就是 规则+过程。

过程管理模型定义了活动、关系、顺序、产出标准等信息。包括以下特征：

  1. 有明确的目标
  2. 可重复性
  3. 可衡量性
  4. 明确的服务提供者和服务对象
  5. 对特定事件的响应
  6. 本身的执行需要相应的信息输入

过程识别和定义

  1. 目标
    1. 过程符合可行性、适用性
    2. 过程稳定，可重复使用
    3. 过程符合效率、效益要求
    4. 过程可被监控和管理
    5. 过程可追溯、可审计
    6. 过程可被衡量和评价
  2. 活动
    1. 识别客户服务内容、范围、目标、管理要求过程，最终目标是交付合格的服务结果
    2. 识别需要的过程及过程目标常用过程，包括需求管理、事件管理、问题管理等
    3. 定义角色和职责对应选择的过程定义相应角色
    4. 识别过程的活动
    5. 定义相关活动详细操作规程及衡量标准
    6. 定义过程的表单及信息记录保存要求
    7. 定义过程评价、评估及改进机制

过程KPI设计

  1. 目的
    1. 分层细化过程KPI，确保过程可管理性、可衡量性
    2. 控制风险，消除因未明确定义而引发的潜在风险
    3. 对过程进行定期评价与衡量，改进调整KPI设计，保持过程有效性
  2. 原则：SMART原则
  3. 活动
    1. 确定KPI指标
    2. 明确KPI计算方法
    3. 定义KPI考核周期
    4. 定义过程KPI评价、评估及改进机制

过程监控设计

  1. 目的
    1. 确保过程执行的规范性、有效性
    2. 及时发现过程执行中的问题，采取应对及改进措施
    3. 对过程本身进行评估，持续改进优化过程
  2. 活动
    1. 过程监控
    2. 过程审计
    3. 过程KPI考核

IT服务部署

目标与定义

IT服务部署实施时衔接IT服务规划设计与IT服务运营的中间阶段，负责对服务组件进行客户化。IT服务部署实施的定位时将IT服务运营纳入标准化与规范化的管理轨道。

  1. 运作机制：IT服务部署实施定义详细的运作机制
    2。 持续改进机制：IT服务部署实施为IT服务运营规划了持续提升的轨道。
    1. 协调并组织组成服务的所有要素
    2. 以标准化的部署实施过程，提升交付质量
    3. 提高相关方的满意度
    4. 确保新服务与变更与客户业务组织、业务过程的衔接
    5. 确保服务或变更的正常运作，并且可以被有效管理
    6. 为IT服务运营提供标准化与规范化的管理方法
    7. 为IT服务运营提供切实可行的服务质量管理方法和指导

    2. 计划制订

        1. 系统规划与管理师
        2. IT服务总监
        3. 客户接口人
        4. 运维工程师
      3. 项目情况
      4. 各阶段具体工作任务与负责人
      5. 交付物列表
      6. 验收标准
      7. 对客户的要求
    3. 计划评估与确认
    4. 计划修订
  3. 关键成功因素
    1. 对IT服务能力和资源合理准确预测
    2. IT服务连续性保障
  4. 可能的风险与控制
    1. IT服务部署实施计划的完整性和条理性
    2. IT服务部署实施计划本身的可用性
      1. 可操作性
      2. 可交付性
      3. 可控制性

  3. 关键成功因素
    1. 分配项目任务

    4. 检查项目问题

    9. 管理项目交付物

IT服务部署实施验收

  1. 注意要点
    1. 服务级别协议中约定的目标均已实现
    2. 规定的服务交付物可合规交付并被客户所验收
    3. 解散部署实施团队并释放资源
    4. 总结并记录部署实施中的经验
  2. 活动
    1. IT服务部署实施期报告
    2. IT服务实施部署回顾
    3. 交付物验收
  3. 关键成功因素
    1. 客户满意度
    2. 客户对服务质量的直接感受
    3. 服务级别协议的完成情况
  4. 可能存在的风险
    1. 验收标准或准则不够清晰
    2. 服务验收准备不充分
    3. 客户主管组织结构变动

IT服务运营管理

人员要素管理

  1. 是否有成熟的知识管理体系
  2. 岗位培训是否充足且适用
  3. 团队能力的互备性
  4. 人员考核指标设定是否符合SMART原则
  5. 人员考核结构应用是否真正落地有效

人员储备与连续性管理

  1. 目标
    1. 保持IT服务连续性
    2. 保持客户对IT服务的信心和信任
    3. 保持供应商及第三方接口关系的连续性
    4. 保持供应商及第三方的信心
  2. 活动
    1. 预防性活动
      1. 服务能力规划
      2. 知识管理及培训
      3. 岗位互备及轮岗
      4. 识别能力发展曲线
      5. 明确岗位交接管理说明
      6. 与客户、第三方、供应商的人员连续性管理
    2. 被动性活动
      1. 岗位交接培训
      2. 面向客户及服务团队进行人员更换说明
      3. 人员连续性安全管理

人员能力评价与管理

  1. 目标：建立人员能力模型，对人员能力进行评价与分析，提供人员能力培训与晋升的信息
  2. 活动
    1. 建立岗位职责能力需求说明书
    2. 建立人员能力现状评估和差异分析表

人员绩效管理

  1. 目标：根据评价结果建立人员能力提升或者工作改进的方法
  2. 活动：
    1. 绩效考核成果报告
    2. 绩效考核成果分析
    3. 基于绩效考核分析的改进
      1. 管理改进
      2. 培训
      3. 激励
      4. 改变绩效方案

人员培训计划执行

  1. 目的：确保有效执行人员计划并确保培训效果
  2. 活动
    1. 按人员培训计划进行培训
      1. 企业内训
      2. 外部培训
      3. 拓展训练
    2. 对培训效果进行评价

    4. 应急预案实施统计
    5. 监控点和阈值统计

  4. 服务过程测量

    1. 服务管控测量
    2. 服务执行测量
      1. 事件统计分析
      2. 问题统计分析
      3. 变更与发布统计分析

  1. 服务回顾机制
  2. 与客户回顾内容
  3. 团队内部回顾内容

成功关键因素

  1. 根据违规记录，进行违规根源分析并加以校正
  2. 基于回顾报告，从满足业务和客户的需求出发，进行调整和改进
  3. 进行精细的服务管理变更控制
  4. 服务回顾的更新要满足业务和客户对IT服务能力的需求
  5. 避免重要的服务回顾内容项缺失，应采用全面严谨的服务回顾模板及会议纪要模板
  6. 避免服务回顾会议延期
