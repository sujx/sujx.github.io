项目的特征

  1. 项目是临时的
  2. 项目是独特的

小型项目的定义

  1. 项目周期短，时间不超过6个月，项目团队成员为非全职投入
  2. 团队成员不超过10人
  3. 涉及的技能领域少；
  4. 拥有单一的目标和易于实现的解决方案
  5. 具有狭窄的范围和定义
  6. 影响单个业务部门，并且只有一个决策者
  7. 能够获得项目信息，不需要从外部项目获得自动化解决方案
  8. 项目经理是首要的领导者和决策者
  9. 不涉及政治问题
  10. 产生直观的可交付成果，技能领域之间的相互依赖小
  11. 有可用资金

项目管理定义

  • 项目管理是指通过应用知识、技能、工具和技术来满足项目的需求，包括澄清项目需求、定义和规划必要的工作、安排项目活动、监测和控制项目活动、与项目干系人交流项目进展情况，以及展开结束项目的活动。
  • 项目经理是被指派实现项目目标的人，负责完成项目
  • 项目管理是门艺术，因为它包含了人的因素
  • 项目管理是一门科学，是因为它是建立在可重复的过程和技术之上。
  • 项目管理是科学的艺术，学习基础科学是实践艺术的必要条件

项目管理的价值

  1. 有助于组织实现商业目标
  2. 提供建立专业领域的程序和工具，以及组织管理项目数据的方法
  3. 提供定义范围和控制范围变化的方法
  4. 确定项目的角色和责任
  5. 允许项目经理管理利益干系人的期望
  6. 允许团队专注于优先事项
  7. 平衡范围、进度、成本、资源、质量和风险等制约因素

小型项目的挑战

项目规划
  • 一定要制定计划
    • 计划可以界定范围、工作内容和成本
    • 计划是团队与利益干系人的一个沟通工具
    • 计划可以控制项目
    • 计划可以跟踪变化
    • 计划可以预测潜在问题，并提供主动管理的手段
    • 计划使你专注于商业目标
  • 让与项目相关人员参与到制订项目计划的过程中
  • 使用合适的工具和技术来管理项目
  • 计划不要过于简洁也不要过于详细
  • 尽量不要用过去的经验来安排项目
  • 获取商业计划书

管理和领导小型项目

管理者使正确做事情的人，领导者使做正确事情的人。管理者使高效的，领导者使有效的。只有将效率和效果结合起来，才是一个好的项目经理。

项目整合管理

  1. 将项目的各个层面联系在一起
  2. 制定项目章程、制定项目管理计划、指导与管理项目工作、管理项目知识、监控项目工作、实施整体变更控制、结束项目
  3. 执行项目管理计划中规定的工作
  4. 监控项目活动

项目范围管理

  1. 确保项目团队做且只做所需的全部工作，以成功完成项目的各个过程
  2. 明确那些工作会包括在项目内、那些不在项目内
  3. 规划范围管理、收集需求、定义范围、创建WBS、确认范围和控制范围
  4. 审查和批准项目交付成果
  5. 确定范围变更的影响，并在变更之前获得批准

项目进度管理

  1. 确保管理项目按时完成所需的各个过程
  2. 包括规划进度管理、定义活动、排列活动顺序、估算活动持续时间、制订进度计划、控制进度

项目成本管理

  1. 为使项目在批准的预算内完成而对成本进行规划、估算、预算、融资、筹资、管理和控制的各个过程
  2. 包括规划成本管理、估算成本、制定预算、控制成本

项目质量管理

  1. 把组织质量政策应用于规划、管理、控制项目和产品质量要去，以满足干系人期望的各个过程
  2. 包括规划质量管理、管理质量、控制质量

项目资源管理

  1. 包括识别、获取和管理所需资源，以成功完成项目的各个过程
  2. 包括规划资源管理、估算活动资源、获取资源、建设团队、管理团队和控制资源

项目沟通管理

  1. 为确保及时且恰当地规划、收集、生成、发布、存储、检索、管理、控制、监督和最终处置项目信息所需的各个过程
  2. 包括规划沟通管理、管理沟通、监控沟通
  3. 可以通过制定沟通矩阵、编写状态报告来完成

项目风险管理

  1. 包括规划风险管理、识别风险、开展风险分析、规划风险应对、实施风险应对和监督风险的各个过程
  2. 风险是计划外的事件

项目采购管理

  1. 包括识别需要外包的项目/资源、制定采购管理计划、与供应商签订合同、监控采购
  2. 提供管理合同的框架，解决如何获取组织外资源的问题

项目干系人管理

  1. 项目干系人四指对项目产生积极或者消极影响或者受项目影响的任何人
  2. 干系人管理解决两个问题：
    1. 谁是我的项目干系人？
    2. 我如何让我的项目干系人参与进来？
  3. 包括识别干系人、规划干系人管理、管理干系人参与、监督干系人参与

领导小型项目

领导一个项目需要权威、职责和责任。

  1. 以良好的人品赢得团队的信任和尊重
  2. 了解自己，熟练履行项目职责
  3. 寻求解决方案，成为问题的解决者
  4. 了解团队成员，努力与他们建立良好的关系
  5. 培养良好的沟通能力，快速响应项目干系人的要去
  6. 指导项目干系人，为他们提供建议、解决眼前的问题
  7. 引导和培养项目团队成员，然后将项目责任下放

领导并不是要有一个头衔，而是要有追随者。“如果你认为你在领导，却没有人追随你，那么你只是在散步”。

项目前活动

项目通常从项目发起人开发业务文档开始，其中包括商业案例和项目收益管理计划。对于简单项目，可以使用工作说明书。

商业文件

  • 项目商业案例：描述项目实现收益的可行性，列出项目的启动目标和原因。
  • 项目效益管理计划：描述了何时、如何交付项目的效益以及如何衡量这些效益。

工作说明书

项目请求

记录商业需求、描述产品范围，并概述潜在的项目，并向决策者提出审批要求。主要包括以下内容:

  1. 业务信息
    1. 业务领域
    2. 商业机会
    3. 连接到战略目标
    4. 识别项目最终客户
  2. 项目描述
    1. 项目要实现的目标
    2. 项目中要包含的内容
    3. 预计完成日期
    4. 初步资金预算
  3. 项目信息
    1. 假设：规划中被认为正确、真是、确定的因素
    2. 问题：识别出有问题或有争议的观点和事项，或者存在分歧的观点
    3. 风险：识别任何不确定的事件或者条件
    4. 验收标准：确定如何知道项目是完整、成功的

启动

定义一个新项目或者现有项目的一个新阶段，授权开始该项目或者阶段的一组过程。

启动步骤

  1. 获取项目论证文件
  2. 识别项目干系人
  3. 访谈项目发起人和其他干系人
  4. 起草项目章程
  5. 识别假设和制约因素
  6. 与干系人一起审查项目章程
  7. 获得项目发起人批准并开始规划项目

项目章程

项目章程明确项目与组织正在进行的工作的关系，以及项目目标与组织战略目标之间的联系。对于小型项目，项目章程需要明确项目目标与业务部门目标之间的联系。项目章程是小型项目管理过程中最重要的文件之一。

项目章程的内容包括以下内容

  • 项目描述
    • 背景信息：概述项目目标和业务目标
    • 项目目标：SMART原则（明确的、可衡量的、可达成的、切实的、有时间限定的）
    • 项目范围
    • 范围内
    • 范围外
    • 项目预算
    • 里程碑概要
  • 项目信息
    • 高层级可交付成果
    • 假设
    • 制约因素
    • 技术决策
    • 对其他项目的依赖
    • 整体项目风险
  • 关键项目干系人
    • 项目发起人
    • 项目经历
    • 其他项目干系人
    • 核心团队成员
  • 支持信息
    • 业务流程影响
    • 验收标准
  • 项目章程的批准
    • 项目发起人
    • 客户

小型项目的规划

规划是为确定工作、定义和完善目标以及制定实现这些目标所需的行动方针而执行的过程。规划是一个反复的过程。规划是项目成功的关键，因为这是项目经理定义和记录项目细节的地方。

规划的步骤

  1. 准备规划活动
    1. 审查项目章程以及项目前的任何文件
    2. 回顾以前项目经验教训
    3. 召开规划会议
  2. 收集需求
    1. 项目需求是项目或产品的需求或期望
    2. 需求表明了如何完成可交付成果
    3. 记录项目发起人的需求和期望，收集其他干系人的问题
    4. 需求应该清晰明确，可以记录在档
  3. 制定项目范围说明书
    1. 详细描述项目交付物以及完成这些交付物所需的工作
    2. 可用于项目控制
  4. 制定工作分解结构
    1. 可以是一个简单的层次结构，只显示主要或高级别可交付成果，也可以更详细
    2. 确保包含所有项目组件
    3. WBS是一种将项目工作分解为组件的工具，是对项目团队为实现项目目标、创建可交付成果而需要实施的全部工作范围的层级分解
    4. WBS的开发方法有两种：
      1. 自上而下
        1. 列出最终产品
        2. 确定主要交付成果
          1. 确保包括项目的所有工作
          2. 制定一个显示等级关系的编号方案
        3. 与干系人会面，审查主要可交付成果
        4. 将主要可交付成果分解为足以满足项目需求的详细程度
        5. 确定编号方案
        6. 与干系人合作完善WBS
        7. 落实最低层级可交付成果的责任人
      2. 自下而上
  5. 制定活动清单和里程碑清单
    1. 活动清单列表：完成项目所需的计划活动，体现为项目进度表
    2. 里程碑清单：项目的重要时点或事件，零持续时间，使用活动来安排工作
  6. 估算工作量和持续时间
    1. 估算工作量
      1. 三点估算法：
        1. 最可能时间
        2. 最客观时间
        3. 最悲观时间
        4. 计算持续时间
      2. 自下而上估算法
    2. 估算持续时间
  7. 制定项目进度表
    1. 关键进度术语
      1. 活动
      2. 活动顺序
      3. 并行
      4. 后继活动或任务
      5. 里程碑
    2. 项目进度表
      1. 甘特图
      2. 里程碑图
      3. 电子表格
  8. 制定项目预算
    1. 估算级别
      1. 数量级估算：项目早期
      2. 相对估算：大型项目估算
      3. 绝对估算：自下而上的估算
    2. 估算方法
      1. 类比估算
      2. 参数估算
      3. 自下而上估算
      4. 三点估算
  9. 确定质量标准
  10. 确定并获取资源
  11. 计划、识别、评估和应对风险
    1. 风险管理规划
    2. 风险识别：识别风险并建立风险登记册
    3. 风险分析：对风险进行量化和排序
      1. 计算风险概率
      2. 估算影响等级
      3. 登记风险负责人
    4. 风险应对规划
      1. 上报
      2. 规避
      3. 转移
      4. 减轻
      5. 接受
  12. 制定沟通文件
    1. 干系人登记册
    2. 沟通矩阵
    3. 责任分配矩阵
      1. 责任分配矩阵
        1. R：执行
        2. A：负责
        3. C：咨询
        4. I：通知
      2. 责任类型
        1. A：批准
        2. C：创建
        3. I：通知
        4. R：审查
        5. S：支持
    4. 项目日志
  13. 制定采购管理计划
  14. 更新假设日志
  15. 制订项目管理计划
  16. 获取发起人的批准

计划成功的关键

  1. 计划并准备重新计划
  2. 让项目工作人员参与工作计划
  3. 利用头脑风暴会议让团队参与
  4. 利用决策工具和技术促进规划过程
  5. 在项目计划中包括项目进度表以外的内容，并包括所有计划文件
  6. 收集项目需求并确定项目范围
  7. 记录假设和约束条件
  8. 了解组件间的逻辑关系并为其制定计划
  9. 可以使用项目管理软件
  10. 协商关键项目资源
  11. 充分利用以前项目的经验教训
  12. 将项目文件保存在项目笔记本中，并建立电子归档系统
  13. 如果没有规划，你将无法控制项目
  14. 获得发起人批准

控制

对于小型项目而言，执行、监督和控制项目活动是结合在一起的，简单可以称为控制。

  • 执行过程组包括“完成项目管理计划中确定的工作，以满足项目要求的一组过程‘
  • 监控过程组包括”跟踪、审查和调整项目进度与绩效，识别必要的计划变更并启动相应变更的一组过程’

控制过程活动

控制就是将实际绩效与计划绩效进行比较、分析差异，并在必要时提出适当的纠正措施。在小型项目管理中，控制还包括协调人员和资源、管理利益干系人的期望，以及监控正在进行的项目管理活动。

控制活动不是按顺序进行的。以下是控制活动的清单：

  • 更新项目进度
  • 控制成本
  • 准备状态报告
  • 管理问题
  • 更新风险登记册
  • 评审和批准可交付成果
  • 管理变更
  • 更新项目进度表
  • 控制成本
  • 准备状态报告
  • 管理问题
  • 更新风险登记册
  • 评审和批准可交付成果
  • 管理变更

行动方案

控制成功的关键

  • 仔细监控项目进度，应对差异，并与利益干系人沟通
  • 管理问题和风险，必要时上报
  • 识别所要求的变更对项目资源、进度和预算的影响，并在获得批准后将变更纳入项目
  • 有一个积极的态度，特别是在困难时期

收尾

收尾是正式完成或关闭项目、阶段或合同而开展的过程。收尾意味着完结一个项目或阶段所定义的过程均已得到妥善处理，并正式确定项目已完成。

小型项目容易收尾，重点是管理收尾，更确切的说是交付项目输出及结束项目。项目经理需要收集项目的记录，分析项目的成功或失败，总结经验教训，撰写项目结项报告，归档项目信息以备未来使用。

收尾活动

  • 关闭项目文件
    • 回顾项目计划，确保所有工作已完成
    • 撰写及分发项目结项状态报告，通知干系人项目已完成
    • 确保没有严重的问题遗留，所有问题状态都应该被关闭
    • 确认是否有项目风险需要转交给运营环节
    • 审核项目预算，确定超预算结果
  • 评估项目
    • 对实际产出和计划进行对比
    • 发放调查问卷收集关键信息
  • 总结经验教训
    • 什么做得好
    • 什么做得不好
    • 那些地方需要改进
    • 是否有建议
    • 过程：
      • 识别
      • 记载
      • 分析
      • 存档
      • 检索
  • 撰写结项报告
    • 结项的原因
    • 结项的职责
    • 项目绩效
    • 绩效与成功标准比对
    • 绩效与计划比对
    • 经验教训
    • 项目庆功
  • 归档项目文件

收尾成功的关键

  • 保证项目目标已完成
  • 保证所有可交付成果已完成
  • 归档项目文档
  • 庆祝项目成功

敏捷。

敏捷是创造和应对变化的能力。它是一种应对不确定性和动荡的环境并最终取得成功的方法。敏捷与其他方法的区别在于，解决方案是通过自组织的跨职能团队之间的协作而不断演进的。

敏捷宣言

  • 个体和互动高于流程和工具
  • 可工作的软件高于详尽的文档
  • 客户合作高于合同谈判
  • 响应变化高于遵循计划

敏捷原则

  1. 我们最优先考虑是通过尽早和持续不断地交付有价值的软件来使客户满意
  2. 即使在开发后期也欢迎需求变更
  3. 采用较短的项目周期，，不断地交付可工作的软件
  4. 业务人员和开发人员必须在整个项目期间每天一起工作
  5. 围绕富有进取心的个体而创建项目
  6. 不论团队内外，传递信息效果最好且效率最高的方式使面对面交谈
  7. 可工作的软件是测量进展的首要目标
  8. 坚持不懈地追求技术卓越和良好设计，从而增强敏捷能力
  9. 以简洁为本，最大限度减少工作量
  10. 最好地架构、需求和设计出自自组织团队
  11. 团队定期反思如何能提高成效，并相应调整自身地行为
